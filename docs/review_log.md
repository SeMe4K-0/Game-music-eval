# Журнал ревизии перед прогоном (2026-09-04)

Полная проверка логики кода, методики и текста до первого запуска на RTX 3060.
Каждый пункт: что было не так → что сделано. Пункты «РЕШЕНИЕ» — за автором.

## A. Критические ошибки (дали бы неверные числа или уронили бы прогон)

1. **Сиды повторялись между наборами.** `for seed in range(12)` для каждого
   set_idx → у детерминированных пайплайнов diffusers наборы 0..K-1 были бы
   побайтно одинаковы, межнаборный разброс = 0, CI вырожден.
   → `seed = base + 100000·set + 1000·prompt + track` (configs/durations.yaml).
2. **FAD на 12 файлах одного промпта.** Ковариация 512-мерных CLAP-эмбеддингов
   по 12 точкам вырождена; FAD-inf не строится. → Единица FAD/KAD — набор
   уровня (модель × D), объединяющий все 8 промптов (96 файлов); промпт как
   фактор анализируется только по per-track метрикам.
3. **Аудио NES-VMDB — не 15-секундные клипы.** По README репозитория аудио —
   полноразмерные MP3 партитур NES-MDB; 15 с — это видеофрагменты (с игровыми
   SFX в дорожке). `corpus_prep.py` переписан на окна длиной D из полных
   партитур; текст статьи и docs исправлены.
4. **Stable Audio Open при D>47 с обрезался до 47 с под меткой 60/90/120.**
   Метрики такта считались бы для несуществующей длительности.
   → Клетки помечаются NOT_APPLICABLE и не генерируются (см. РЕШЕНИЕ 1).
5. **Метрики использовали заявленную, а не фактическую длительность.**
   → Фактическая длительность пишется в manifest и берётся из wav.
6. **Модель загружалась с диска на каждый трек** (`from_pretrained` внутри
   функции генерации): ~10 000 загрузок весов. → `ModelRegistry` (одна
   модель в памяти за раз, освобождение между моделями).
7. **Возобновление прогона падало**: `set(record.items())` на записи с
   вложенными dict → TypeError. → ключи загружаются в set один раз.
8. **CLAP получал аудио не на 48 кГц.** `ClapFeatureExtractor` не ресемплирует
   (проверено по документации) и для fusion-чекпойнта требует `is_longer`.
   → явный ресемплинг + `is_longer`; зафиксирован RNG fusion-кропов.
9. **API ACE-Step / Riffusion были выдуманы.** Сверено с исходниками:
   ACE-Step пишет файл по `save_path`, сиды — `manual_seeds` строкой;
   Riffusion: `riffuse(inputs, init_image)` → PIL → `SpectrogramImageConverter`
   → pydub; `SpectrogramParams`: 44 100 Гц, моно, ≤10 кГц, клип 5.12 с.
10. **MusicGen «продолжение» было независимой перегенерацией** одинакового
    промпта → жёсткие стыки каждые 30 с. → настоящая audio-continuation через
    `processor(audio=...)`; лимит 30 с включает промпт (1503 токена).
11. **Имя эмбеддера `clap-music` не существует** в fadtk → `clap-laion-music`.
    Парсер «последнее число в stdout» для `--inf` вернул бы slope/r², не FAD.
    → эмбеддинги через fadtk API, FAD/KAD на numpy по одним эмбеддингам,
    бутстрап по файлам; тулкиты — только для кросс-проверки точечных значений.

## B. Ошибки в определениях метрик

12. **Лучшая точка разреза допускала петли от 2 с**: минимум расстояния
    тривиально находился у самого конца трека. → петля ≥ 50 % длительности;
    поиск в обе стороны (обрезка начала и конца); score нормирован на ту же
    внутритрековую статистику.
13. **Порог для шва «пол-метрика + порог» не определён** (пол существует
    только для FAD/KAD). → самокалибрующийся порог: шов ≤ p95 внутритрековых
    переходов того же масштаба + щелчок ≤ p99 |Δ| самого трека.
14. **Пик лаг-профиля SSM всегда на лаге 1** (соседние кадры тривиально
    похожи) — метрика мерила гладкость, не периодичность. → лаги [1 с, n/2].
    Тест на периодичность был некорректен (у чистого тона постоянная
    хромаграмма) — заменён на 4-нотный паттерн.
15. **Дрейф темпа = октавные скачки детектора**, не дрейф. → свёртка локальных
    темпов в октаву глобального.
16. **Относительные мажор/минор считались сменой тональности.** → сравнение
    ключевых сигнатур.
17. **Период доли = медиана квантованных интервалов** (0.511 вместо 0.500 с
    при hop 23 мс) — на 32 долях ошибка 0.35 с = 0.17 такта у идеального
    сигнала. → регрессия времени доли по индексу.
18. **`beat_track(y=...)` обнуляет огибающую** (медиана по мел-полосам) на
    разреженном сигнале и `trim=True` отбрасывает крайние доли. → явная
    onset-огибающая, `trim=False`.
19. **Метрики считались на нативной частоте модели** (16 vs 48 кГц) и без
    нормализации громкости → несопоставимы между моделями; пики >1.0
    клиппились при записи PCM16. → общая analysis_sr=22 050, пиковая
    нормализация, запись PCM_24.
20. **SSM 120 с при hop 512 на 48 кГц — ~1 ГБ** на трек; chroma_cqt
    пересчитывался на каждое окно. → hop 2048 (~10 fps), признаки один раз.
21. **Пол через EnCodec** — пол только для MusicGen. → split-half пол (идеальный
    генератор) + per-model round-trip: EnCodec, Oobleck VAE (SAO), Griffin-Lim
    (Riffusion); AudioLDM2/ACE-Step — TODO фазы 0.
22. **Стингер (fanfare) участвовал в шовных условиях**, хотя не зацикливается
    по определению. → `loop_eval: false`.

## C. Неточности в тексте и цитатах

23. Авторы NES-VMDB: Cardoso, Moraes, Ferreira (было выдумано «Cardenuto»).
24. KAD: Chung, Eu, Lee, Choi, Nam, Chon; ICML 2025.
25. CLAP-чекпойнт `laion/larger_clap_music` — это LAION CLAP (Wu et al.,
    ICASSP 2023), а не Microsoft CLAP (Elizalde et al.).
26. CLAP видит 10-секундные фрагменты (fusion); fadtk режет файлы на 10-с окна
    с шагом 1 с — единица статистики FAD «окно», не файл. Оба факта — в
    ограничения статьи.
27. Riffusion: эффективная полоса ≤10 кГц при 44.1 кГц выхода.
28. Число генераций полного плана (24 000) — теперь с учётом дробного плана и
    N/A-клеток SAO: см. experiment_design.md.

# Ревизия 2, 2026-09-04 (вопрос про бесплатные GPU)

## E. Блокирующая находка: вырожденный выход проходил игровые критерии

**Проверено эмпирически, не гипотеза.** Прогон метрик на синтетике:

| выход | seam_naive_ok | bar_fraction_error | tempo CV | key drift |
|---|---|---|---|---|
| тишина | **True** | — (degenerate) | ~0 | 0 |
| постоянный тон | **True** | **0.039** (порог 0.1 — проходит) | **0.0** | **0.0** |
| белый шум | **True** | 0.124 | 0.030 | 0.82 |

То есть модель, выдающая гудок или тишину, получала бы идеальные оценки по
структуре и проходила шовный критерий: чем меньше в сигнале музыки, тем
«лучше» шов, темп и тональность. Риск не теоретический — AudioLDM2 на 120 с
работает в 12 раз дальше своей обучающей длины (10 с), Riffusion склеивается
из 24 клипов.

Сделано:
- `src/metrics/degeneracy.py` — детектор на устойчивых признаках: спектральный
  поток (тишина 0.00, гудок 0.011 против мелодии 0.69 и аккорда 2.7),
  спектральная плоскостность (белый шум 0.56 против тональной музыки ≤0.001),
  исходный пик до нормализации, доля тишины.
- `dynamic_range_db` и `onset_rate` в правило НЕ вошли: у аккорда с ровными
  ударами динамический диапазон 1.3 дБ при 6.9 у мелодии, а у чиптюна с
  квадратной волной — 0.0 дБ, то есть критерий забраковал бы легитимный
  целевой жанр. Онсет-детектор на постоянном тоне даёт ложные 9.3 события/с.
- Пороги калибруются по референсу (`src/calibrate_degeneracy.py`, 1-й
  перцентиль NES-VMDB), а не берутся константой — та же логика, что у
  самокалибрующегося порога шва.
- Вырожденный трек в решающем правиле считается **не прошедшим**, а не
  исключается: иначе модель с 90 % тишины отчиталась бы по оставшимся 10 %.
- Уровни до нормализации (`orig_peak`, `orig_rms`) пишутся при генерации:
  после пиковой нормализации трек с исходным пиком −57 dBFS неотличим от
  нормального.

## F. Исправления под раздачу работы по площадкам

29. **Один сид на разном железе не даёт одно аудио** — схема common random
    numbers между площадками не работает, и железо могло стать скрытым
    фактором, спутанным с моделью. Отпечаток среды (GPU, capability, версии)
    пишется в каждую запись манифеста; шардирование — по клеткам
    (модель × длительность), клетка целиком считается на одной площадке.
30. **bfloat16 отсутствует на T4/P100/M4000** (появился в Ampere, sm_80), а
    ACE-Step просит его по умолчанию. Тихое понижение до fp16 сделало бы
    точность скрытым фактором. dtype прибит в `configs/models.yaml`,
    `src/env_info.py` падает с объяснением вместо подмены. Следствие:
    ACE-Step недоступен на Kaggle/Colab, только Ampere+ (3060, L4, A100).
31. **85 ГБ аудио невозможно возить между площадками** (Kaggle сохраняет
    20 ГБ, Drive 15 ГБ). `src/remote_worker.py`: генерация, метрики и
    эмбеддинги в одной сессии, аудио удаляется после метрик, наружу уходят
    метрики и эмбеддинги (~1 ГБ). Архивный сэмпл `--keep-audio sample`
    обязателен, т.к. перегенерация на другом железе не воспроизводит аудио.
32. Ложные предупреждения `divide by zero / overflow / invalid encountered in
    matmul` в матрице самоподобия — это баг Accelerate BLAS на macOS
    (воспроизводится на заведомо конечной случайной матрице, результат
    конечен). Погашены через `np.errstate` с явной проверкой конечности,
    чтобы настоящий NaN не проскочил вместе с ложной тревогой.

## G. Что теперь проверено без GPU

`tests/` — 26 тестов: 21 юнит-тест метрик и статистики плюс 5 сквозных на
подставных бэкендах (план → генерация → метрики → вырожденность → сводка →
решающее правило). Ключевая проверка: модель-гудок не проходит правило, хотя
её шов и дрейф темпа формально идеальны. Также проверено, что шардирование
покрывает каждую клетку ровно один раз, сиды уникальны между наборами,
повторный запуск не генерирует заново, а длительность выше нативного максимума
фиксируется как «не применимо» и не создаёт аудио.
